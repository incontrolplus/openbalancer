System Overview & Capabilities #

OpenBalancer is an ultralight, non-blocking asynchronous load balancer and API reverse proxy engineered for AI token streaming, high-frequency microservices, and zero-downtime operations.

💡
AI Agent & LLM Integration Context: For automated coding agents (Claude, ChatGPT, Gemini), we provide structured API specifications and OpenAPI 3.1 endpoints directly at /openbalancer/status and /metrics.

Traditional reverse proxies incur significant buffer allocation and thread contention penalties when handling long-lived Server-Sent Events (SSE) or bi-directional WebSockets. OpenBalancer eliminates intermediate buffers by piping raw socket descriptors directly through Python's non-blocking asyncio event loop.

Core Architectural Capabilities

  • Zero-Buffer SSE Streaming: Unbuffered chunk-by-chunk piping for OpenAI/Claude/vLLM completion endpoints.
  • Proactive Circuit Breaking: Tripping unhealth backends in <50ms upon consecutive 5xx errors or connection timeouts.
  • Multi-Algorithm Routing: Least Latency, Weighted Round-Robin, Least Connections, IP Hash, and Power-of-Two (P2C).
  • Built-in Prometheus Exporter: Native /metrics scraper without external exporter sidecars.
  • Zero-Downtime Hot Reload: Immediate in-flight re-configuration via POSIX SIGHUP signals.

Kernel & Event Loop Architecture #

OpenBalancer utilizes single-threaded non-blocking cooperative multitasking via Python's asyncio socket event loop (~18MB RSS footprint).

⚡
Zero-Copy Bufferless Streaming Pipeline: When proxying streaming responses (e.g. OpenAI/Claude SSE completion streams or gRPC chunks), OpenBalancer bypasses internal aggregation buffers and streams chunks directly between socket descriptors in real time.

Circuit Breaker & Health Probing State Machine

State Trigger Condition Routing Behavior Recovery Process
HEALTHY Health check returns HTTP 200 OK within timeout limit. Receives full traffic proportional to its configured weight. Steady-state health probes every probe_interval seconds.
PROBING / DEGRADED Single probe failure or latency spike > 500ms. Traffic throttled; candidate for isolation. Probed with accelerated frequency until confirmed or tripped.
TRIPPED / DOWN consecutive_failures >= threshold (default: 3). Immediately isolated. Zero ingress traffic routed to this node. Background probes continue until 2 consecutive 200 OK probes restore health.

Routing Algorithms #

OpenBalancer provides 6 production-ready load balancing strategies switchable at runtime or via configuration:

Algorithm Identifier Routing Logic Best For Complexity
round_robin Distributes requests evenly in circular sequence across all healthy backends. Homogeneous backend nodes with uniform request cost. O(1)
weighted / weighted_round_robin Routes traffic proportional to each node's capacity weight integer (e.g. 3:2:1). Heterogeneous servers (e.g., 8-GPU node vs 2-GPU node). O(1)
least_latency / latency Directs incoming requests to the backend with the lowest recent health check latency. Multi-region backends or variable inference workloads. O(N)
least_connections / least_conn Selects the healthy node with the lowest number of active open TCP sockets. Long-lived HTTP/1.1 connections, WebSockets, SSE streams. O(N)
ip_hash / consistent_hash Hashes client source IP (MD5 hash ring) to bind client sessions to a sticky backend. Stateful web sessions, cache locality, sticky user state. O(1)
power_of_two / p2c Picks two random healthy nodes and routes to the one with fewer active connections. Massive clusters avoiding the herd effect with O(1) selection overhead. O(1)

Configuration Schema (`config.json`) #

OpenBalancer reads its initial topology from config.json. All parameters can be hot-reloaded without downtime via SIGHUP.

Property Type Default Description
host string "0.0.0.0" Network interface to bind the ingress listener to.
port integer 8080 Port for the load balancer ingress proxy.
algorithm string "least_latency" Dispatch algorithm: least_latency, round_robin, weighted, least_connections, ip_hash, power_of_two.
health_check_interval integer 3 Interval in seconds between background HTTP health probes.
circuit_breaker_threshold integer 3 Consecutive failures required before tripping a backend node.
backends array [] Array of upstream nodes with host, port, weight, and health_path.

Production Deployment & Docker #

Deploying OpenBalancer in mission-critical environments with automatic restart policies, healthchecks, and resource constraints.

Complete Production Docker Compose Stack

YAML 
services:
  openbalancer:
    image: ghcr.io/incontrolplus/openbalancer:v1.5.0
    container_name: openbalancer-core
    restart: always
    ports:
      - "8080:8080"
    volumes:
      - ./config.json:/app/config.json:ro
    environment:
      - OPENBALANCER_LOG_LEVEL=INFO
      - OPENBALANCER_WORKERS=1
    healthcheck:
      test: ["CMD", "python3", "-c", "import urllib.request; urllib.request.urlopen(\"http://localhost:8080/openbalancer/health\", timeout=2)"]
      interval: 10s
      timeout: 3s
      retries: 3
    deploy:
      resources:
        limits:
          cpus: "2.0"
          memory: 256M

Zero-Downtime Hot Reload (`SIGHUP`) #

OpenBalancer listens for POSIX SIGHUP signals. When received, the core re-reads config.json from disk, reconstructs upstream pools, updates routing weights, and resets connection counters without closing active socket streams.

BASH 
# Send SIGHUP to running Docker container
docker kill -s HUP openbalancer-core

# Or via PID on standalone host:
kill -HUP $(pgrep -f openbalancer.py)
